# Growth Experiment Lab 求职展示说明

## 项目背景

这是个人开源、合成数据作品集，不是公司项目或生产系统。我希望把实验设计、随机化检查、
效果估计和观察性因果分析放进一条可执行、可测试且不会泄漏模拟真值的流程。

## 架构与本人工作

配置驱动合成数据生成，DuckDB SQL 构建用户级 mart，数据契约后分别进入实验设计与随机化
诊断、随机 A/B ITT 分析和观察性 stabilized IPTW，最后自动生成 Markdown 报告。全部代码、
统计方法、测试、CLI、文档与 CI 均在本项目中实现。

## 分析亮点

- 随机实验：样本量/MDE、SRM、SMD、A/A、风险差、Welch、Bootstrap、Holm、护栏、CUPED 和预定义分群。
- 观察性分析：固定处理前白名单、逻辑倾向模型、overlap/positivity、稳定化 Hájek IPTW、ESS、Love plot 与重拟合 Bootstrap。
- 工程化：固定种子、TOML 配置、可安装 src 包、DuckDB、CLI、自动报告、pytest、ruff、GitHub Actions 和端到端 smoke test。
- 防泄漏：正式估计只读分析 mart；合成真值只由独立验证命令读取，且不会导出到公开示例。

## 主要局限

所有数据均为合成数据；随机实验结果不能外推到真实产品。IPTW 依赖 positivity、模型设定和
无未观测混杂，不能消除未测量混杂。项目不实现序贯检验、AIPW、matching 或生产部署。

## 三条中文简历描述

1. 独立构建基于合成数据的增长实验作品集，以 Python、DuckDB SQL 和用户级数据契约串联实验设计、随机化诊断、ITT 效果估计与自动报告。
2. 实现 Bootstrap、Holm、CUPED、护栏阈值和预定义分群交互检验，并通过固定种子、单元测试和 CI 保证统计流程可复现。
3. 实现观察性数据 stabilized IPTW ATE 分析，包括倾向得分、overlap、ESS、加权 SMD、Love plot 和每次重拟合倾向模型的用户级 Bootstrap；在隔离流程中用合成真值验证方法。

## 90 秒面试介绍

我做这个项目是为了把增长实验中常见但容易分散的工作放进一个可复现框架。数据是固定
随机种子的合成用户数据，因此可以预设效果并独立验证估计器，但正式报告绝不读取真值。
随机实验部分先定义 `user_id` 为实验单位、次日留存为主指标并做样本量和 MDE 规划，再用
SRM、处理前 SMD 和独立 A/A 检查随机化。效果分析按首次分组做 ITT，报告效应大小、区间、
显著性、Holm 校正、负反馈护栏、CUPED 和预定义新老用户交互。之所以再做 IPTW，是为了
展示非随机处理下如何用处理前变量评估 overlap、权重、ESS 和加权平衡，并用 Hájek 形式估计
ATE。Bootstrap 每次重新拟合倾向模型。主要局限是数据为合成数据，而且 IPTW 无法解决未观测
混杂，所以报告始终要求人工复核，也不包装成生产平台。

## 常见面试追问及答案要点

1. **为什么主指标不做 Holm？** 它是唯一预先指定主指标；Holm 只覆盖 clicked 与观看时长次要指标族。
2. **为什么观看时长包含零值？** 随机入组用户都是 estimand 的组成部分，过滤零值会形成处理后选择。
3. **SRM 通过代表什么？** 仅表示未发现组别人数相对预期分流的显著异常，不证明全部随机化正确。
4. **为什么用 SMD？** 它比显著性检验更直接描述协变量标准化差异，且不把样本量当成平衡质量。
5. **CUPED 的前提？** 协变量必须为处理前变量；统一 theta，目标是降低方差而非放大效果。
6. **为什么 IPTW 用处理前变量？** 处理后变量可能是中介或碰撞点，会改变目标效应并引入偏差。
7. **为什么 AUC 不是倾向模型主标准？** 倾向模型服务于平衡和 overlap，而不是处理预测排名。
8. **ESS 为什么重要？** 名义样本大不代表加权信息量大；变异权重会降低有效样本量。
9. **为何 Bootstrap 重拟合 propensity？** 固定 propensity 会遗漏倾向模型估计不确定性。
10. **如何避免真值泄漏？** 正式模块只读 mart；独立验证模块才读 metadata，综合报告和 examples 均排除验证文件与真值字段。
