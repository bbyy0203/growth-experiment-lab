# 数据质量与泄漏边界

本项目只处理合成数据，不代表真实公司数据或生产实验平台。本阶段的数据质量输出仅为
描述性检查，不执行组间效果比较、显著性检验或因果推断。

## 原始表职责

- `users`：只包含实验前定义的用户属性和历史行为。
- `assignment`：包含用户处理标记、数据集类型及模拟机制使用的真实分配概率。
- `outcomes`：只包含实验期观测结果。

三张表必须拥有完全相同的用户集合，每张表中 `user_id` 唯一，关联关系严格为一对一。

## 正式 mart

随机实验和观察性数据分别生成一张 `experiment_mart.parquet`，粒度均为一名用户一行。
SQL 必须显式选择字段，不能使用 `SELECT *`。这样即使原始模拟表未来新增潜在结果或
生成真值，字段也不会静默泄漏到分析底表。

正式处理前协变量仅包括：

- `device_type`
- `region`
- `is_new_user`
- `pre_7d_sessions`
- `pre_7d_watch_time_minutes`
- `pre_7d_click_days`
- `pre_experiment_activity_score`

`assignment_probability` 是合成机制的真实概率，不进入 mart；未来倾向得分只能用上述
处理前协变量重新估计。`true_effects.json` 不参与 SQL 构建或正式效果估计。

## 检查范围

验证覆盖文件存在性、字段白名单、必需字段、缺失值、唯一键、用户集合、关联行数、
数据集隔离、二元取值、数值范围、日期可解析性以及明显真值字段。SQL 结果还会与 pandas
独立 merge 逐列交叉验证。

JSON 摘要包含用户数、处理与对照人数、处理比例、缺失与重复计数、二元指标总体均值、
观看时长分布和处理前变量基础分布。它不包含潜在结果、真实 ATE 或组间效果估计。
